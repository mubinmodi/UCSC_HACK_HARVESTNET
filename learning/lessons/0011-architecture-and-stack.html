Architecture and stack

What runs where, and what each sponsor does.

After this lessonYou can sketch the architecture from memory and give each sponsor's role in one line.

The pieces

  • Households: mobile web page or voice line, then the front-desk assistant, which saves request records with no names.
  • Agents: one for each donor and each food bank, plus the advocate. They negotiate in the AGNTCY room over A2A messages.
  • Directory: finds food banks by capability, for example when a cooler fails.
  • Shared records: draft versions, holds, approvals, and outcomes.
  • n8n: turns records into text alerts and approval requests.
  • Dashboards and the evaluation runner: read the records but can't change any decision.
  • Beeceptor: stands in for each organization's own systems: inventory, storage, cooler status, and truck schedule.

Sponsors, one line each

  • Cisco AGNTCY: A2A messages and Directory discovery. Skip SLIM group chat, which is marked experimental.
  • ElevenLabs: the voice line, with English and Spanish read-back.
  • n8n: alerts, approvals, and the "can't make it" release.
  • Beeceptor: mock systems, plus the switch that makes a cooler fail.
  • AWS: hosting. Claude API: the agents and the assistant.

None of them decides anything (ADR 0004).

See the AGNTCY app-sdk README and the A2A specification.

On AWS

One EC2 machine running Docker Compose. Each organization's agent gets its own container, alongside the web app and API, the AGNTCY Directory, and Postgres. There's one public HTTPS address, so n8n and ElevenLabs can reach the system, and keys are kept in Secrets Manager. n8n, Beeceptor, and ElevenLabs stay on the sponsors' own servers.

Models

Opus 5.5 for food banks and the advocate, Sonnet 5.5 for donors and the front desk, and no AI for scoring. This assignment is proposed.
