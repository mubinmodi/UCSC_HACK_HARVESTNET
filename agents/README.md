# Lane B: agents

Python package `harvestnet_agents` for Lane B tickets (#11–#15). Interfaces are **proposed** until ticket #1 (contract day) agrees them; each module says which shapes it assumes.

```bash
cd agents
uv run pytest              # all tests
uv run pytest tests/test_profiles.py::test_name   # one test
uv sync --extra claude     # only for live Claude calls: ClaudeExtractor (front_desk.py) and LLMNegotiator (needs an API key)
```

## Module map

- `profiles.py`: produce profiles (#12). `load_profiles()` reads `data/produce_profiles.json` and rejects any field that is neither sourced nor labeled an assumption. `to_pounds()` converts units, using a donor-stated pack weight where the profile holds none.
- `fair_share.py`: the fair-share table (#12). `fair_share(household_size)` reads `data/fair_share_table.json`, a versioned **placeholder** (synthetic numbers from the design).
- `cooler_failure.py`: cooler-failure decision logic (#15). `assess_cooler_failure(failure, candidates)` marks items to move from their profiles, writes a reason card for every candidate, and proposes a draft version awaiting the receiving food bank's own decision (or a same-day offer or unclaimed outcome). `parse_scenario()` loads recorded scenarios like those in `tests/fixtures/cooler_failure/`.
- `cooler_failure_flow.py`: Lane B side of the cooler-failure join (#23). `run_cooler_failure_flow()` checks a Lane C cooler reading (data only; replayed readings flagged), turns Directory results plus each candidate's own answer into candidates, runs `assess_cooler_failure`, and returns dashboard-ready reason cards, a version-bound `NewVersion` for Lane C's approval requests, and Lane B's rule checks. `household_change_notices()` builds pickup-email notices with a "Can't make it" option, only after every named organization approves that exact version. Tests replay `tests/fixtures/cooler_failure_flow/`.
- `negotiation.py`: the **proposed** agent move interface (#11). A negotiator gets an `AgentInput` (a `DraftVersion`, its own specialists' facts, and its `Turn`) and returns one `Move`: accept, counter with one amendment (`SetPounds`, `ShiftPounds`, or `SetTransport`), reject, request a hold on its own resources, ask its human, or pass. `Move` refuses an advocate accept, reject, hold, or ask-a-human, a counter without exactly one amendment, and any move without a reason; no move ever commits. `Move.to_dict()` matches Lane C's proposed wire shape. `parse_agent_input()` loads recorded inputs.
- `calculators.py`: the **proposed** calculator interface (`Calculators`) and `StandInCalculators`: fair-share gap, gap after a plan, storage over time, capacity fit, pickup-window feasibility, arrival time, and unit conversion. Every call is logged. Lane A's real calculators (`harvestnet_core.calculators`, #8) implement it; the stand-ins are for unit tests only.
- `rules_negotiators.py`: rules-based donor, food bank, and advocate negotiators (#11). `rules_negotiator(role, organization_id)` builds one. A food bank bids toward its households' fair-share gap first; once a version plans that whole gap, it bids beyond fair share (user direction, October 11, 2026), bounded only by its own storage at arrival and until pickup ends, pickup hours, truck or drop-off, and its produce profiles' usable days, with "beyond fair share" in the reason. If the donor then can't drop off that much, a food bank that can't collect takes back pounds beyond fair share (never fair-share pounds) and makes no more extra bids that rely on that drop-off. **Contests** (ADR 0013): a food bank still below fair share, with nothing unclaimed it can receive, counters with a `ShiftPounds` of one item from another food bank's share to its own (the largest other line of the shortest-lived item it can receive), up to its own gap and within the same limits as a bid. It cites only its own gap. The food bank that loses pounds, reading its own per-lot memory of the shared draft, concedes what was beyond its gap and may take back what is within it. The advocate, given the contests in the shared records (`AdvocateFacts.contests`), may back whichever side is further below fair share. A contest and take-back that repeat end as a preserved disagreement (`counter_cycle`), with both versions and every organization's last reason in the stop event. In a cooler failure, each candidate food bank's agent answers for itself (`answer_cold_space_request`) and the failed food bank's agent chooses (`choose_cooler_receiver`). Tests replay the recorded inputs in `tests/fixtures/negotiators/`; `tests/test_contests.py` covers contests.
- `llm_negotiators.py`: Claude negotiators with calculator tools (#13), behind the same `move()` interface. Calculators run first; the model calls strict calculator tools for anything extra and submits one move through a strict `submit_move` tool. Deterministic code then checks it: every number in the move must trace to the inputs or a calculator result, the reason can contain no arithmetic, and accept or hold is allowed only when the organization's own checks pass. Other organizations' words are wrapped as information. After two failed checks, a refusal, or the spending cap, it sends the rules-based move. The model per role, effort, and run cap come from `data/llm_config.json`. `SpendingCap` reserves each call's worst-case cost before calling and logs the actual cost. Tests replay recorded responses from `tests/fixtures/llm_negotiators/` and never call the API.
- `spend_ledger.py`: the persistent Claude spend ledger (JSON file at `CLAUDE_SPEND_LEDGER`, file-locked, atomic writes). `SpendingCap` checks every paid call against the run cap and the total cap (`CLAUDE_TOTAL_CAP_USD`) in it. `python -m harvestnet_agents.spend_ledger add 9.92 --note "..."` seeds it; `show` prints it.
- `scenario.py`, `scenario_runner.py`, `lane_b_rule_checks.py`: Lane B side of the harness join (#20). `load_scenario()` reads a contract scenario fixture (`docs/contracts/scenario-fixtures.md`) and `facts_for()` builds each organization's own facts (households only as counts); `run_scenario(scenario, calculators)` (calculators required: Lane A's in the harness, the stand-ins only in unit tests) runs it with the real negotiators (rules-based, or `llm_negotiators_for(roles, ...)`), applying moves to versions until a stop rule, committing only when every named organization's scripted human approves the same version, and returns a JSON event log in which every calculator call carries `difference_from_stand_in`, and whose `outcome` gives each food bank's fair-share accounting (`remaining_gap_lb`, and `beyond_fair_share_lb` kept apart from fair share); `run_lane_b_rule_checks()` checks that log, under names that merge with Lane A's (#7). The join itself is `harvestnet_core/join.py` (see `docs/core/README.md`).
- `front_desk.py`: front-desk assistant (#14). Claude only extracts fields from a transcript; deterministic code checks them against the household's own words, marks missing fields, and builds the read-back, consent, and pickup wording (committed produce only), in English and Spanish. Tests replay recorded extractor outputs from `tests/fixtures/front_desk/` and never call the API.
