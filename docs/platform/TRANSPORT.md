# Organization hosts, transport and discovery

Each organization with an agent (`market`, `city`, `rural`, `eastside`, `advocate`; list in `harvestnet_platform/roster.py`) runs its own host. On its organization's turn the core asks that host for its move; the host runs its own negotiator and returns one proposal, signed with its own key. It has no way to accept, hold or commit for anyone: there is no commit endpoint. Transport authentication (below) proves who sent a message; it is not a human or an organization approval.

## What runs

- **Default host:** `python -m harvestnet_platform.transport --organization <id>` is a small A2A JSON-RPC host, labeled `a2a_jsonrpc`. `compose.platform.yaml` runs one container per organization. The donor's container keeps the service name `donor` (`http://donor:8020`) and hosts `market`.
- **Native AGNTCY host:** `python -m harvestnet_platform.agntcy_server` wraps the same receiver in the official App SDK (`requirements-agntcy.txt`), labeled `agntcy_native`. It takes the same `--organization`, `--port` and `--host` arguments (or `ORGANIZATION_ID` and `PORT`), so `HARVESTNET_ORG_HOST=harvestnet_platform.agntcy_server` swaps it in under `compose.platform.yaml`; `compose.agntcy.yaml` also runs it. It needs `TRANSPORT_VERIFY_KEYS`, and `TRANSPORT_SIGNING_KEY` to answer move requests; it checks each signature before the SDK sees the request (401 otherwise). No SLIM group chat is used. Idle, one native host used about 144 MiB against 39 MiB for the JSON-RPC host (measured once on a laptop; indicative only), so five of them are a large share of the t4g.small's 2 GB and AWS keeps the JSON-RPC host by default.
- **Policy:** `AGENT_POLICY=module:function` selects the policy a host runs. `harvestnet_core.join_adapter:policy` is the real rules-based negotiator with the real calculators. `harvestnet_core.join_adapter:llm_policy` is that organization's own Claude negotiator under the host's own cap (`CLAUDE_RUN_CAP_USD`, `CLAUDE_TOTAL_CAP_USD`, `CLAUDE_SPEND_LEDGER`); with no cap it makes no model call and answers with its rules move, labeled `fallback`. On AWS the hosts sit on the internal network with no API key, so a Claude host policy there would also need outbound access and the key; that is not set up. Without a policy a host answers with a labeled synthetic stand-in (`ask_human`, or `pass` for the advocate), which is only for transport tests.
- **On AWS** the hosts are the JSON-RPC ones with the Directory SDK, running the real rules policy (`AGENT_POLICY=harvestnet_core.join_adapter:policy`), and the core requests every live move from them (below). The three food bank hosts also run their own cooler watcher (`COOLER_WATCH=1`, `harvestnet_core/cooler_watch.py`). See [`deploy/aws/README.md`](../../deploy/aws/README.md).

**How it fits.** Live moves are requested over signed A2A from each organization's own host; the AGNTCY Directory is for discovery. The core publishes the turn, checks the reply and applies the move to the shared records; it makes a move for an organization only when that organization's host could not answer, and then it says so (`in_process_fallback`). `harvestnet_platform.join` is a separate check: it runs one fixture in process and over the five hosts and requires identical outcomes ([`JOIN.md`](JOIN.md)). The hosts also publish the Directory records that food banks search when a cooler fails. Two things still run in the core: the food bank dashboard's "agent suggests" preview (`API.suggestion`, a read-only look at the current version, not a move) and the scripted harness and evaluation (`run_fixture`), which stay in process so results are repeatable.

## Move requests: the live path

The core (`harvestnet_core/move_transport.py`, `HARVESTNET_MOVE_TRANSPORT=a2a`) uses `harvestnet_platform.moves.A2AMoveProvider` for every turn of a live lot (`negotiate_pending`, after an offer, a counter, a condition check, a decline or an expired hold):

1. **Request.** It sends the organization whose turn it is, and only that organization, a `message/send` whose one DataPart is `{kind: "move_request", event_id: "move-<random>", sequence: 1, turn, input}`, signed as `core` for that organization. `input` is the agent input in the core's wire form (`turn` as the organization ID, the turn object in `turn_context`, plus `policy_session`, so each host keeps one negotiator per organization across a lot's turns, as the core does). Its `facts` are that organization's own and nobody else's, computed by the core from its records (the same facts the core validates commitments against). Before sending, the core checks them with the agents' rule (`_facts_problems` in `lane_b_rule_checks`: a donor's or food bank's facts carry its own ID, the advocate gets counts only, and no facts name a household's request code). A turn that fails that check is never sent.
2. **Host.** The host verifies the signature, refuses a move request for another organization, runs its own policy, and replies with `{kind: "move_reply", event_id: "<org>:<request id>", in_reply_to, turn, move, host: {organization_id, transport, policy, policy_metadata}}`, signed with its own `TRANSPORT_SIGNING_KEY` for `core` (`transport.answer`). A host with no signing key of its own refuses move requests. An identical retry returns the saved move, signed again.
3. **Check.** The core accepts the reply only if it is signed by that organization's own key for `core` (checked with `TRANSPORT_VERIFY_KEYS`, the keys the organizations derived for `core`), fresh and not replayed, answers this request, names that organization as host and turn, and carries one valid move of that organization's on the current version (`validate_move`). An unsigned or forged reply, a reply from another organization's host, or a move for another organization is refused.
4. **Fallback, labeled.** A timeout (`AGENT_TURN_TIMEOUT_SECONDS`, 15 on AWS), an unreachable host, a host error or a refused reply makes that turn's move with the core's own in-process rules negotiator for that organization, and records it as `move_source: in_process_fallback` with the reason. That organization's host is asked again after `MOVE_HOST_RETRY_SECONDS` (default 30), so a hung host does not hold every later turn for the whole timeout. The fallback negotiator does not share the host's memory of earlier turns in the lot.
5. **What is recorded.** Before each live `move` event the core records a `move_source` event: `a2a` (with the host's `transport`, `a2a_jsonrpc` or `agntcy_native`), `in_process_fallback` (with the reason), `in_process_template` (two failed number checks), `staff_counter` (queued by the organization's staff) or `in_process` (no provider). A `policy_provenance` event keeps the host's policy and, for a Claude policy, its source, calls, cost and number check failures (which count toward the lot's total). `GET /lots/{lot_id}/versions` lists each move's source (`moves`, and `move_source` per version) without fallback error text; the food bank dashboard counts them per lot (`move_sources`) and lists that organization's own fallbacks with their reasons (`our_fallbacks`); and the core's log prints one line per move. The dashboard web page does not show these fields yet.

The same negotiators run either way, so outcomes do not change: the end-to-end test (`core_tests/test_a2a_moves.py`) creates an offer through the API with five hosts on localhost and gets the same moves and lot as in process. With `HARVESTNET_MOVE_TRANSPORT=in_process` (the default outside AWS, and in every other test) the core runs each owner's negotiator itself.

## Ordered exchange (the join's broadcast)

The envelope is `event_id` (the lot ID, contract decision 7), a positive `sequence`, `turn` (the organization ID) and `input`, which is Lane B's agent input unchanged: `{role, draft, facts, turn}` with `turn: {organization_id, number, now, accepted_by}` ([agent moves](../contracts/agent-moves.md)). The core's harness sends `turn` as the organization ID and the turn object in `turn_context`; the transport accepts both forms.

- One caller serializes each event, broadcasts the envelope to every organization, and waits for every acknowledgement before advancing.
- **Only the organization whose turn it is receives `facts`.** Every other host gets the envelope without them, and a host refuses another organization's facts.
- Only the acting organization returns a move. Moves are proposals as in `docs/contracts/agent-moves.md`: accept, counter (exactly one amendment), reject, request its own hold, ask its own human, or pass. The advocate may only counter or pass. None counts as a human approval.
- Sequence order is durable in each host's SQLite receipt log (`RECEIPTS_DB`). An identical retry returns the saved result; a changed retry or a sequence gap fails. After a partial outage, retry the same envelope. Never switch policy or mode inside a running event.
- A turn waits up to `AGENT_TURN_TIMEOUT_SECONDS` (default 60, long enough for a live Claude turn). Other service calls use `HARVESTNET_HTTP_TIMEOUT_SECONDS` (default 10). Plain HTTP outside localhost needs `ALLOW_INTERNAL_HTTP=1`, which the Compose stacks set for the Docker network.

## Who sent it: per-sender signatures

There is no shared transport token. Every sender has its own key, and every envelope is signed (`harvestnet_platform/transport_auth.py`, standard library only).

- **Senders.** The turn publisher, `core` (the process that publishes the negotiation's turns: the live core, and `harvestnet_platform.join`), and each organization.
- **Signature.** HMAC-SHA256 over a canonical body: the scheme, `sender`, `recipient`, `timestamp`, a random `nonce` and the whole envelope (`event_id`, `sequence`, `turn`, `input`). It travels in the envelope's `auth` block and is removed before the receiver and its receipts see the envelope.
- **Pairwise keys.** A sender keeps its own key and derives one key per recipient. A host is given only the keys derived for itself (`TRANSPORT_VERIFY_KEYS`, a JSON map of sender to key), so it can check a message addressed to it but cannot forge one from that sender to another host. Its own key is `TRANSPORT_SIGNING_KEY`.
- **What a host refuses (401).** An unsigned message, an unknown sender, a message addressed to another host, a signature that does not match the claimed sender (including any change after signing), a timestamp more than 120 seconds off, and a nonce it has already seen (kept in the receipts database, so a restart does not reopen the window).
- **Sender and turn.** The turn publisher may publish any organization's turn. An organization may publish only its own turn (`turn` must equal its own ID), and only under an event ID that starts with `<its-id>:`, so it can never step into the publisher's events; the publisher in turn cannot use those names. A host signs its replies to move requests with its own key under exactly that rule (`<its-id>:<request id>`, its own turn).
- **Retries.** A retry is re-signed with a new nonce but carries the same envelope, and the receipt log returns the saved result, so the outage rule above still holds.
- **Keys.** `python -m harvestnet_platform.transport_auth --output runtime/transport.env` writes new keys and every host's derived values to a new 0600 file for local Compose runs. On AWS, `setup.sh` keeps one key per sender in the secret (`TRANSPORT_KEYS`) and `deploy/load_secrets.py` derives each host's values on the instance; compose gives each container only its own (`compose.platform.yaml`).
- **Not covered.** The receipt a host returns to the join's broadcast comes back on the same HTTP exchange and is not signed; the publisher checks its organization, event and sequence. Replies to move requests are signed (above). The private Docker network has no TLS.

## Discovery

The Directory answers "who has cold space and pickup hours for this lot", as a snapshot. It is not a reservation: the candidate rechecks its current facts and holds before anything commits.

- **Records.** Each host registers its own OASF record at startup. It re-reads its own systems every `DIRECTORY_REFRESH_SECONDS` (default 30); a changed capability publishes a new record and removes the old one. Search keeps the newest record per organization and filters cold capacity and pickup time.
- **AWS.** `deploy/aws/compose.directory.yaml` adds a private AGNTCY Directory daemon at `directory:8888` (the official `dirctl daemon`, which includes the search indexer; the standalone apiserver needs a separate reconciler, per the [AGNTCY local deployment guide](https://docs.agntcy.org/dir/dir-deployment-local/)). `deploy/aws/check_directory.sh` is the post-deploy check.
- **Elsewhere.** Set `AGNTCY_DIRECTORY_ADDRESS` and install the SDK from `requirements-agntcy.txt`.
- **The CLI.** `python -m harvestnet_platform.directory --list`, `--brief --cold-lb 100 --pickup-at 2026-10-13T19:00:00-07:00`, or `--register` (seeds all five synthetic records by hand; needs `AGNTCY_DIRECTORY_ADDRESS` and `AGENT_ENDPOINTS`, a JSON map of organization to URL).
- **Fallback.** With no Directory address the CLI uses the local registry and says so (`local_directory_fallback`). If a configured Directory is unreachable and `AGENT_ENDPOINTS` is set, it prints the labeled fallback and exits 2. A fallback result is never presented as an AGNTCY result.

References: [AGNTCY app-sdk](https://github.com/agntcy/app-sdk), [Directory SDK](https://docs.agntcy.org/dir/directory-sdk/).
